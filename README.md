# Менеджер заявок на доступ до лабораторії (Лабораторна робота №4)

## Виконання вимог на оцінку "Відмінно"

### 1. Контракти та версійність
* **Версійність:** Усі API-ендпоінти використовують префікс `/api/v1/` для забезпечення стабільності контрактів.
* **Правила сумісності DTO:**
  1. **Адитивність:** Нові поля (наприклад, `user_name`) додаються як необов'язкові.
  2. **Незмінність:** Існуючі назви полів (`user_id`, `access_type`) не змінюються, щоб не зламати клієнтів.
  3. **Дефолтні значення:** Якщо поле відсутнє в запиті, сервіс використовує логічні значення за замовчуванням.

### 2. Технічна реалізація
* **Frontend:** Повністю написаний на **TypeScript** з суворою типізацією DTO.
* **Надійність:** Реалізовано `AbortController` для автоматичного скасування запитів через 10 секунд.
* **Обробка помилок:** Система коректно обробляє помилки мережі (CORS, відсутність сервера) та помилки валідації (400/500).

### 3. Сценарії перевірки (QA)
1. **Успішне додавання:** Заповніть форму, натисніть "Додати". Очікуйте статус 201 у консолі та оновлення таблиці.
2. **Видалення:** Натисніть "Видалити" на будь-якому записі. Підтвердіть дію.
3. **Помилка сервера:** Зупиніть `node server.js` та спробуйте оновити дані. UI покаже повідомлення "Помилка мережі".
4. **Таймаут:** (Для тесту можна штучно уповільнити сервер). Клієнт скасує запит через 10 секунд.

## Як запустити
1. **Компіляція TS:** `cd frontend` && `npx tsc`.
2. **Backend:** `cd backend && cd src && node server.js` (запуск на порту 3000).
3. **Frontend:** Відкрити `frontend/index.html` через Live Server (порт 5500).
